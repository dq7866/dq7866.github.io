# 人体积木 · 拆开看结构，装回懂身体

> **v1.5.0 · 商业发布候选（2026-11-15）**：65 形状 / 13 套生理动画 / 6 个病理病例 / 7 套主题 / 本地多档案 / 视频工坊与影片模式；已完成发布级审核、启动兜底、存档自愈、无障碍与许可署名收口。发布门禁 `tools/verify-release.cjs` 在源码版、单文件版、线上等价环境三套环境全绿。

把骨骼、肌肉、器官拆成 47 个可独立操作的「形状」，每个形状带 **7 项功能作用** + **注意事项** + **守护提示**；另有 18 个**日常认知部位**（头发、眼睛、嘴唇、脸颊、手指、脚趾……），合计 65 个形状。玩家在 3D 人体上点选、拆下、再装回，用拆解与搭建两条链路记住结构的功能和健康意义。

**模型是真实解剖网格，不是堆方块。** 634 块解剖结构（骨骼 198 块、深/浅层肌肉 362 束、牙齿软骨眼球外耳，加 CT 分割的 115 个脏器）按结构名合并成 47 个可拆装形状，运行时约 22 万三角形。

**看得懂结构，也看得到它怎么运转。** 13 套程序化生理动画——血液循环（含脑循环与四肢循环）、消化吸收（含饮水与肾过滤）、神经控制（运动指令 + 感觉回传）、呼吸换气、免疫防御、淋巴回流、内分泌调节、运动联动，以及泌尿过滤（肾小球滤过→重吸收→膀胱储尿排尿）、吞咽与发声（会厌开合 + 声带振动）、运动响应（跑步时心率/呼吸/血流重分配）、损伤修复（止血→骨痂→重塑）、视觉与听觉（光线聚焦视网膜 + 声波经鼓膜耳蜗）——把路径、粒子与器官形变叠在真实模型上，右侧按站点同步讲解。另有视频工坊与 6 个常见病的病理课堂。

**「正常人体」整人视图。** 左侧系统第一条「正常人体」是默认视图：骨骼（淡）、肌肉（主体）、器官（透出轮廓）三层同时可见，呈现一具完整、正常站立的人，方便从整体认识身体；点开任意形状仍能读它的七项功能。

**「日常人体」独立版块。** 第二条系统「日常人体」呈现日常看到的裸身人：头发、眼睛、鼻子、嘴、嘴唇、牙齿、脸颊、耳朵、颈、胸、腹、手臂、手、手指、腿、脚、脚趾 18 个一眼能认的部位，全部为肤色体块程序化建模，可直接点选拆装；认完外面，再进解剖那几层看里面。

**7 套主题外观，含 2 套明亮主题。** 顶栏调色盘按钮一键换装：深色氛围 5 套（深空蓝默认、墨黑银、翡翠青、暗夜紫、暖夜橙）+ 明亮主题 2 套（晴空白、暖纸白）。一次同时改界面配色（CSS 变量驱动，含顶栏、模式开关、主按钮、选中态）、3D 场景（背景、雾、地面、网格、微尘、呼吸光环）、影棚打光（半球光/主光/轮廓光/补光的色温与强度）与浏览器 `theme-color`；明亮主题还会把卡片、按钮、弹窗的玻璃叠层与文字翻成深色，正文对比度 ≥ 4.5，3D 背景取比 UI 略深一档的浅灰蓝/米白，象牙白骨骼仍有轮廓。选择存在 `localStorage`，刷新后仍生效，清空学习进度不会清掉主题。

**本地用户档案。** 顶栏的人像按钮（或昵称标签）打开「我的档案」：新建、切换、重命名、删除档案，多人共用一台设备时每人的已认识形状与徽章各自独立。首次进入会把旧版单存档**无损**搬进默认档案「我」；切换 / 新建会重载页面以彻底重建内存状态。这是纯本地档案，不注册、不登录、不上传、不联网，换设备或清缓存不会同步；「清空进度」只清当前档案。需要真正的账号体系与跨设备同步，得另外接后端服务。

**自愿赞赏。** 程序完全免费、无广告、无追踪：顶栏「赞赏」按钮和左侧「请作者喝杯咖啡」卡片都能打开微信 / 支付宝收款码弹窗，可把二维码保存到相册再扫。收款码只是一张静态图片，不经任何服务器、不影响任何功能、不收集任何信息；金额随意，不给也完全不影响使用。

**发布级健壮性与合规。** 启动链有三层兜底：WebGL 能力预检、顶层脚本异常与未处理 Promise 捕获、`boot()` 失败兜底——任一环节出问题都显示可操作的错误卡片与「重新加载」，而不是永远停在加载页；显卡上下文丢失也会提示恢复。存档读取会校验字段类型、过滤未知形状 id、防 `__proto__` 原型链命中，并把损坏数据自愈写回，旧版本或手工改坏的 `localStorage` 也不会白屏。无障碍方面：全站 `:focus-visible` 高对比焦点环、3D 画布可用方向键旋转 / `+ -` 缩放 / `0` 复位、`toast` 带 `aria-live`、viewport 允许自由缩放、遵循系统「减少动态效果」。帮助面板常驻展示 CC BY-SA 4.0 / CC BY 4.0 数据集署名与改编说明、版本号、隐私边界和健康科普免责声明；页面带 OG / Twitter / canonical 分享元信息与 `assets/og-cover.png` 封面。

## 运行

- **最简单**：双击 `人体积木.html`（单文件版，样式、脚本与模型全部内联，无需服务器）。
- **源码版**：在目录内起静态服务器再访问 `index.html`：
  ```bash
  python -m http.server 8765
  # 浏览器打开 http://127.0.0.1:8765/index.html
  ```
- 纯前端、纯本地：不上传数据、不联网、无账号（只有本地档案）、无广告；进度按档案隔离，只存在浏览器 `localStorage`。赞赏收款码是一张本地静态图片。

## 玩法

### 探索拆解
1. 左侧切换 **骨骼 / 肌肉 / 器官** 三层，其他层自动变淡，方便看"谁包着谁"。
2. 点击身体上的形状打开知识卡：七项功能作用、注意事项、守护提示。
3. 点「拆下这个形状」把它取下；零件盘里点一下即可装回。

### 重建搭建
1. 切到「重建搭建」，当前层的形状全部拆空，只剩蓝色轮廓空位。
2. 从底部零件盘把形状拖到对应空位（也可点一下形状再点空位）；放错会提示这个位置属于谁。
3. 全部装回自动进入 3 道题的系统挑战，答对 2 题获得该层徽章与守护清单。
4. 想重来，点零件盘右上角「重置本层」。

### 主题外观

点顶栏的调色盘按钮打开面板，7 套配色分成「深色氛围」「明亮主题」两组，各带三色预览：选一套，界面、场景与灯光一起换装；✕ / Esc / 点面板外面都能收起，顶栏按钮也是开关。默认「深空蓝」与加主题之前的观感完全一致，不切换就不会有任何变化。主题选择独立于学习进度，浏览器本地记住。

明亮主题不是把背景刷白就完事：界面里原本为黑底写的白色半透明叠层会整体翻成墨迹色（`--ink-rgb`）与纸面色（`--surface-rgb`），主按钮改白字，正文用深色，冷/暖两套各自给变量；3D 背景刻意比 UI 深一档，避免颅骨与米白背景糊在一起。影片、视频工坊、病理课堂刻意保留深色沉浸画面：影片字幕是白字，进场一律压成影院黑并收起地面/网格/微尘，退出后按当前主题整体回填；工坊的 X 光黑底也不会被主题色盖掉。生理动画在明亮主题下血流粒子反而更清楚。

拖拽旋转、滚轮缩放、Shift + 拖动平移。音效可关；「清空进度」只重置当前档案的学习记录。

### 本地用户档案

顶栏的人像按钮或昵称标签打开档案面板，列出每个档案的已认识数与徽章数，可切换、重命名、删除，也能在输入框里新建（最多 12 字）。每份进度写在独立的 `hb-save-v1::<档案 id>` 键里，档案清单与当前档案写在 `hb-profiles-v1`；老版本写在 `human-body-bricks-v1` 的进度，首次进入会原样复制进默认档案，一条不丢。切换档案会重载页面，避免内存里的 `Set` 状态串档。面板里也如实写明：这些档案只存在于这台设备，**不上传、不联网、无账号密码**，换设备或清缓存不会同步——它不是云端账号，跨设备同步需要另接后端。

### 支持作者

顶栏带文字的「赞赏」按钮和左侧面板顶部的「请作者喝杯咖啡」卡片，都会打开赞赏弹窗：左边是你的微信 / 支付宝收款码，右边是扫码步骤与「保存二维码」按钮（单文件版里图片已内联成 data URI，离线也能保存）。弹窗在深色与浅色主题下都保持可读，二维码始终白底。打赏完全自愿，不影响任何功能；程序不联网、不追踪、不收集任何信息。

### 生理动画

顶栏的脉冲按钮打开动画条，13 套生理过程可以随时切换（动画条可左右翻页/横向滑动）：

| 动画 | 看什么 | 同步的结构动作 |
| --- | --- | --- |
| 血液循环 | 肺循环、体循环、脑循环、四肢血管里红蓝血细胞的流向 | 心脏按 72 次/分做收缩—舒张跳动 |
| 消化吸收 | 食物沿食管→胃→小肠→大肠→直肠推进；水在小肠被吸收；肾过滤后入膀胱 | 胃揉搓、小肠蠕动波 |
| 神经控制 | 运动皮层→脑干→脊髓→臂丛/腰骶丛→手和脚的运动指令，以及感觉回传 | 肱二头肌、股四头肌在冲动抵达时抽动 |
| 呼吸换气 | 空气经鼻、咽、气管、支气管进出肺泡，吸气蓝、呼气灰 | 膈肌下降变平、肋骨上抬、肺膨胀 |
| 免疫防御 / 淋巴回流 | 白细胞巡逻吞噬病菌；组织液经淋巴结单向过滤回静脉 | 脾脏搏动、病菌被吞噬消失 |
| 内分泌调节 / 运动联动 | 激素随血到靶器官的负反馈；肌肉收缩牵动骨骼绕关节摆动 | 心肝肾与四肢联动 |
| 泌尿过滤 | 肾动脉入球→肾小球滤过→肾小管重吸收→集合管→输尿管→膀胱→排出 | 肾单位搏动、膀胱充盈与排空 |
| 吞咽与发声 | 食团入咽时会厌盖喉、食管蠕动；呼气气流让声带振动成声 | 会厌开合、声带高频振动 |
| 运动响应 | 动脉加速灌腿、静脉回流、呼吸变快变深、内脏血流让路 | 快心率、肺大幅张缩、摆臂迈腿 |
| 损伤修复 | 血小板止血→骨痂与肉芽生长→血栓机化再通→受力重塑 | 骨折端细颤与肿胀、骨痂渐定形 |
| 视觉与听觉 | 光线经角膜晶状体聚焦视网膜→视神经入脑；声波经鼓膜听小骨到耳蜗→听神经入脑 | 鼓膜振动、视网膜与皮层亮点交替 |

右侧面板按当前阶段讲解（每套 4–7 站），进度条跟着循环走；可以暂停、0.6×/1×/1.6× 调速。进入动画时三层结构一起转成半透明（这一层的材质 `depthWrite` 会关掉），否则里面的流动看不见；退出时缩放、位置、透明度全部还原。

动画是纯程序化的，没有额外资源：`src/physio.js`（前八套）与 `src/physio-extra.js`（补完的五套）里每套动画由若干条 `CatmullRomCurve3` 路径 + `TubeGeometry` 管体 + `InstancedMesh` 粒子组成，粒子按弧长匀速前进，颜色沿路径插值（例如体循环在毛细血管段由红转蓝）。路径坐标取自 `body.glb` 的真实包围盒（单位米），比例差异由 `k = bodyMeta.height / 1.71` 校正，所以换模型也不会飘。

| 日常人体 | 18 | 头、头发、眼睛、鼻子、嘴、嘴唇、牙齿、脸颊、耳朵、颈、胸、腹、手臂、手、手指、腿、脚、脚趾 |

共 455 条功能说明、65 条注意事项、65 条守护提示、15 道系统挑战题。`src/data.js` 里的 `validateData()` 会检查每个形状是否恰好 7 项功能。

**骨块粒度**：脊柱拆成颈椎（C1–C7）、胸椎（T1–T12）、腰椎（L1–L5）、骶骨、尾骨；胸廓拆成肋骨与胸骨；前臂拆成桡骨与尺骨；小腿拆成胫骨与腓骨；手拆成腕骨／掌骨／指骨；足拆成跗骨／跖骨／趾骨。每张知识卡额外列出「本块含 N 项骨性结构」，例如腕骨卡会列出舟骨、月骨、三角骨、豌豆骨、大多角骨、小多角骨、头状骨、钩骨——**47 个拆装单元背后是 200 余块真实骨**。

> 膈肌与尾骨在 Écorché 数据集中没有独立网格，用程序化造型补位；其余 45 个解剖形状都是真实解剖网格。「日常人体」的 18 个部位同样为程序化肤色体块（模型数据集不含体表部位）。
> 另有 304 束小肌肉（手内肌、肋间肌、足底肌等）归入「其余肌肉」残差层：只作视觉填充，让身体外形完整，不进零件盘、不参与拾取。

## 烘焙管线（为什么需要它）

原始数据集有两个麻烦：顶点是 int16 量化 + `KHR_mesh_quantization`，每个器官又是 40~600 个碎网格。直接在浏览器里拼装会既慢又容易出错。`tools/cook.mjs` 把这些问题一次性解决在离线阶段：

1. **反量化**：按 glTF 规则把 int16 位置、int8 法线还原成米制 Float32，套上节点变换。
2. **按形状合并**：用 `asset-map.js` 的规则把 634 块网格归到 44 个 id，每块只留一份几何。
3. **简化**：`meshoptimizer` 的 `simplify()`，误差优先（默认 0.3 cm 级），薄片肌肉不会被压成碎片；顶点压实，去掉简化后不再被引用的顶点。
4. **标定**：CT 脏器 → Écorché 人体空间。等比缩放取 C7→骶骨 节段长度比；胸骨体前缘对齐防止脏器顶穿胸壁；骨盆下缘对齐；两髋中心对齐中线。颅腔用「眼眶以上的颅骨顶点」估计，把大脑装进去。
5. **归一**：每个形状以自身包围盒中心为原点（中心写进节点平移），全身脚底 y=0、左右前后居中。
6. **写出**：一个无扩展的标准 GLB —— 位置 Float32、法线 int8 归一化、顶点色 uint8、索引 uint32。

产物从 16 MB / 108 万三角形降到 4.5 MB / 22 万三角形，浏览器解析 1.4 秒。

### 增加一套生理动画

1. 在 `src/physio-data.js` 的 `PHYSIO` 里加一条：`id / name / en / color / tag / cycle / intro / steps(带 at 的 4–7 站) / tip`。`at` 是循环内的位置（0–1），讲解与粒子用同一条时间轴。

## 边界说明

- 「本地用户档案」不是账号系统：没有注册、登录、密码、服务端与跨设备同步，数据只在这台设备的浏览器里，清缓存即丢失。赞赏只是一张静态收款码图片，不做支付回调、不记录打赏者、不影响任何功能。
- 内容是面向大众的**健康科普与学习材料**，依据常用解剖学、生理学教材常识整理，未逐条标注页码；不构成诊断或治疗建议，身体不适请就医。
- 3D 模型来自开放解剖数据集，**同一块骨的左右两侧合并在一个形状里**（如股骨、腕骨、肾），拆装时成对移动；器官几何来自一例 CT 分割，个体差异会让比例与真实人体略有出入。
- 拆分粒度停在「骨块」而不是「每块骨一个形状」：24 节椎骨、24 根肋骨、54 块手骨都合在各自的骨块里。理由是搭建链路要让玩家真的能装完——200 余块逐个拖拽会变成折磨，而知识卡里的「本块含 N 项骨性结构」已经把这层知识交代清楚。要再细拆，按上面「增加一个新形状」的流程加规则即可，渲染与交互层不用改。
- 简化后细节有损：极细的肌腱、血管不保留，指尖与足趾的细分被压平。
- 生理动画是**示意性**的：血管、神经、消化道走的是教学常用的简化路径（例如体循环只画主动脉—髂动脉—股动脉主干），粒子速度和器官缩放为了看得清而放慢、放大，不代表真实血流速度或器官形变幅度。真实血管网、肠管盘曲形态远比这里复杂。
- 若用于课堂、出版或医疗相关场景，建议先由解剖学/医学专业人员审校文案与模型比例。
- **安全与性能基线**：运行时零外部请求（无 CDN、无统计、无远程字体），所有资源同源或内联；用户输入（档案名等）一律走 `textContent` / DOM API，不拼 `innerHTML`。未加 CSP `meta`：单文件版与站点访问门都依赖内联脚本与 `data:` / `blob:` URI，强行加严格 CSP 会破坏离线版和录制导出，改用构建期哈希校验 + 发布门禁保证产物完整性。实测基线（Edge 桌面 1440×900）：源码版首屏约 2.0 s / 单文件版约 1.2 s / 线上等价约 2.0 s，稳定 60 FPS，JS 堆约 47–93 MB；单文件 17.6 MB、线上运行时合计 13.7 MB（其中两个 GLB 占 12.2 MB）。
- **窄屏布局**：≤900px 时左侧面板是固定 64px 高的横向工具条，支持卡与系统卡定宽不收缩，可横向滚动；≤420px 时品牌只留小 logo、支持卡收成图标按钮。顶栏右侧图标栏可横向滚动，不会把整页撑出横向滚动条。
