# 自然培育所 · Nature Lab

一款"把一株生命养完整"的网页培育模拟游戏。选择物种 → 调节环境与营养 → 走过 5 个生长阶段 → 收获 → 留下自留种进入下一轮。

## 怎么运行

双击 `index.html` 即可用浏览器打开（纯前端，无需安装、无需服务器）。
如需在局域网/手机上看，可在本目录执行：

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080`。

## 用户与档案（v2.0）

同一台设备可以有多个玩家档案，互不干扰：

- 右上角头像进入「档案与用户」：改名、换头像、新建、切换、删除
- 每个档案拥有独立的 3 个存档位、设置、教学进度、成就与图鉴
- 可选 4–12 位 PIN：启动时锁屏，连续输错 5 次冷却 30 秒
- 「导出当前档案 / 导出全部档案」生成 JSON，换设备后可导入
- 全部数据只存在浏览器 localStorage，不上传、不统计；清理站点数据会连存档一起删除

> PIN 只防同机误入，不是加密。忘记 PIN 无法找回，只能在锁屏页清除该档案数据。

> 加粗的七个是「卵生 / 孵化 / 喂养 / 成长」专题物种，设计上刻意各占一个教学点：绿头鸭讲**早成鸟**、陆龟讲**温度依赖型性别决定**、蚕讲**完全变态 + 人类驯化退化**、仓鸮讲**晚成鸟育雏**（难度 4，全作最高）、鸡讲**产蛋与孵化**、狗讲**社会化窗口期**、猫讲**专性肉食与牛磺酸**。

> 七个物种的"卵"分两路：**卵生**（鸡、鸭、龟、蚕、鸮、蝶、蛙）从一枚蛋开始；**哺乳**（狗、猫、兔）从一窝无毛幼崽开始。两条路在第一阶段都**不进食**——一个靠卵黄，一个靠母乳，玩家能做的只有守住温湿度。

### 卵生与孵化机制

新物种不是"换个皮"的作物，它们把「卵」本身做成了一个需要照顾的阶段：

| 机制 | 实现方式 |
|---|---|
| **孵化期不进食** | 第 1 阶段（卵）营养需求全部为低值，给肥没有任何收益，资源和注意力必须转向温湿度稳定 |
| **破壳期最脆** | 第 2 阶段 `fragility` 拉到 1.4–1.7（作物普遍 1.0–1.2），温度偏移的伤害被放大，一次忘开加温就可能致死 |
| **育雏期高蛋白** | 雏鸟/雏鸭/幼龟/蚁蚕阶段的 N 需求推到 78–90，是全作最高的蛋白档位；同时 P/K 需求压低，"一把复合肥通吃"在这里失效 |
| **成长跨度长** | 卵生物种 `days` 合计 23–32 天（番茄 21 天），加上孵化段不能靠施肥加速，节奏明显更慢 |
| **成体是回报** | `yield.base` 1.4–3.6，成鸟/成犬/成猫单价高于作物，属于"慢但贵"的第二条经济线 |

三只家养宠物（鸡、狗、猫）是这一轮的重点，它们各自对应一个**现实中真的会致命的常识点**：

| 物种 | 会被判死的操作 | 游戏里怎么体现 |
|---|---|---|
| 鸡 | 育雏期温度不足 | 雏鸡阶段 fragility 1.35，温度掉出 12–26℃ 时掉血最快；产蛋期光照不足 5h 则适生分直接掉到 60 以下 |
| 狗 | 断奶期喂牛奶 | 幼犬阶段 N 需求 80（全作第二高），但含水维度上限只有 80%——给太湿会拉稀，对应肠道菌群失衡 |
| 猫 | 只喂谷物 | 幼猫阶段 N 需求 85，是所有宠物里最高的；P/K 需求压到 30–40，逼玩家喂"肉"而不是"复合肥" |

**配套系统**：宠物维度接入了年报（"宠物养成"区块：累计收蛋 / 最高默契 / 满值数 / 抱窝次数）、5 项专属成就（蛋筐渐满、养鸡专业户、抱窝观察员、初次亲近、生死相托）、帮助文档的「宠物养成」分页，以及统计结论里的针对性建议。

**饲养位文案按物种改写**：同一栖息地养不同物种，界面用词必须跟着变。暗室养蚕不叫「基质状态」而叫「蚕座卫生」，蜂箱养仓鸮不叫「巢脾状态」而叫「巢箱卫生」，笼舍养狗叫「犬舍卫生」、养猫是「猫砂清洁」、养鸡是「鸡舍卫生」；含水维度同理（蚕座湿度 / 巢箱湿度 / 水池水位 / 垫材含水 / 饮水水位）。实现上是三层映射：**物种级 → 栖息地级 → 通用兜底**，加物种时只补需要覆盖的那几条。

### 室内栖息地的光照折算

暗室与巢箱不该吃室外日光。正午累计日照 5.6h 时，如果直接套用室外值，**要"几乎无光"的蚕（0–4h）和仓鸮（0–2h）在每天中午都必然被判为光照超标**，玩家怎么调设备都救不回来。

所以 `envFor()` 按栖息地折算：**暗室 ×0.12**（只算门窗漏进的散射光）、**巢箱 ×0.06**（箱内接近全黑）。折算后蚕的正午光照约 0.7h、仓鸮约 0.3h，落在适宜区间内——想让它"更黑"仍然要拉遮阳帘，但至少存在可行解。

### 物种专属维度：产蛋与默契

同一个栖息地里养六种动物，如果全都走"长大 → 按品质卖钱"这一条路，它们就只是换了张皮。所以宠物有三条独立的第二条结算线：

| 物种 | 专属维度 | 怎么算 | 满值回报 |
|---|---|---|---|
| **鸡** | 产蛋量 | 光照 × 蛋白 × 钙 × 资质，**按天累积**，可随时收 | 成鸡期约 0.6–0.9 枚/天，每枚 8–22 币 |
| **狗** | 默契度 | 陪伴次数 + 独处状态 + 环境舒适度 | 售价 **+70%** |
| **猫** | 默契度 | 安静睡眠 − 被打扰 + 环境舒适度 | 售价 **+70%** |

**关键设计：两条线都是"期间持续积累"，不是收获时一次性判定。** 否则玩家会把它当成另一种品质分，而不是另一种玩法。

- **鸡的产蛋期是独立阶段**：`孵蛋 → 破壳 → 雏鸡 → 中鸡 → 开产 → 成鸡`，共 6 个阶段（其余物种仍是 5 个）。"开产"是爬坡，"成鸡"是高峰——产蛋窗口和成长窗口分开，玩家不能只等收获。
- **抱窝**：产蛋期内每天 1.2% 概率进入抱窝，连续 3 天停产。这是真实机制（催乳素升高），也是给玩家的一个"主动收蛋"提醒。
- **软壳蛋**：钙（游戏里由 P 维度承担）低于需求时，产蛋量打 6 折并标注"缺钙·软壳"。
- **狗与猫的养法相反**：狗靠"每天陪一次"（+5.4/天），猫靠"别去打扰它"（安静熟睡 +2.0/天，被吓到 −4.5/天）。同一套 `bondDaily` 用不同的规则表，不写两套代码。
- **情绪直接可见**：舒适度低于 62 时宠物会"躲起来"（狗 −2.6/天、猫 −4.5/天），高于 85 时"熟睡"（猫 +2.0/天）。所以环境没调好时，再怎么陪也涨不上去。
- **长期冷落的负反馈（狗和猫表现刻意相反）**：狗忠诚不走，但默契 < 20 且连续 3 天躲藏后开始**拆家**（每天 35% 概率，修理费 12–35 币，计入统计 `damages`）；猫会先预警一次（默契 < 25 且连续 2 天躲藏，日志提示"总在往门口看"），然后默契 < 12 且连续 4 天躲藏时**离家出走**——槽位清空、不可挽回，档案记一笔 `grade: '出走'`，出走数计入统计 `runaway`。出走 ≠ 死亡：档案里能看到它的默契值和当时的阶段。
- **姿态直接画在场景里**：宠物躲藏时主角会缩到角落、变暗（`pet-hide`），出走预警时会在门口左右徘徊（`pet-pace`），配 HUD 提示牌——不用翻面板就能看出它现在的状态。
- **寻回事件「门口的猫」**：只有出走过的玩家会遇到（事件池加了 `cond` 条件支持）。选择接回：猫回到空位，默契从「接纳」（34）重新开始；选择放行：花 25 币喂它一顿换 30 经验，目送它离开。没有空位时该事件不会出现。接回后把默契重新养到「亲近」可解锁成就「失而复得」。
- **陪玩反馈**：陪狗会开心小跳（`play-bounce`），陪猫只懒懒地侧头、头顶冒粉色爱心（`play-heart` + 爱心粒子）——两种性格连反馈方式都不一样。
- **图鉴宠物档案**：鸡狗猫的图鉴行多一块金色「宠物档案」——鸡显示累计收蛋/抱窝/蛋收入，狗猫显示按物种分记的最高默契（含档位名）、满值数与出走/拆家次数。默契按物种记录在 `stats.bondSp`，蛋收入记在 `stats.eggEarn`。
- **事件季节加权**：事件池贴真实气候——雷暴夏天 ×2.2（冬天 ×0.4）、冰雹与寒潮冬天 ×2.2–2.4（寒潮夏天权重为 0，绝不会出现）。实现是 `EVENT_SEASON_W` 表，`rollEvent` 抽取前按 `seasonForDay` 乘权。
- **栖息地专属事件**：藻华预警（仅水生，夏季 ×2.0）、土壤返盐（仅土壤，夏秋 ×1.5–1.8）、菌包污染（仅暗室，春夏 ×1.3–1.6）——用 `cond` 判断当前培育位是否有对应栖息地的作物，让「专精某条路线」的玩家遇到专属于该路线的风险。三者的"硬扛"选项都会带来真实代价（病害概率 35–45% 或健康 −4~6），与 35–45 币的处理费形成清晰的取舍。
- **自动备份轮换**：每 5 个游戏天自动滚动备份一份，每槽最多 3 份（`naturelab.save.v1.bak{slot}_{1..3}`）。图鉴底部新增「自动备份」区块，显示每份备份的天数/时间/档案数/金币，可一键**回滚到任一备份**（回滚前可先手动导出留底）。这是防手滑的最后一道保险——手动存档只存最新，自动备份留的是历史。

### 场景按物种微调

3D 场景与背景图默认跟随栖息地，但允许按物种覆盖：**绿头鸭住在笼舍里（温度、垫料、卫生都按笼舍算），布景却改成水面池塘**——因为一只水禽站在温室台架上实在违和。实现上是一个 `SCENE_KIND_SP` 表（物种 → 场景类型），命中则用物种的场景，否则回落栖息地。

这也顺带带来一处真实好处：鸭子的设备面板会自动换成增氧泵、生态过滤、换水，因为面板渲染时读的是同一个场景类型。

### 五种栖息地的差异

游戏不是"一种温度一条曲线"，不同栖息地的环境模型本身不同：

| 栖息地 | pH 基准 | 含水维度叫法 | 补水动作 | 特有玩法 |
|---|---|---|---|---|
| 土壤 | 随天气漂移 6.3–6.5 | 土壤含水 | 浇水 | 连作疲劳最敏感 |
| 水池 | 稳定 7.35 | 不适用 | 换水 | 溶氧/氨氮双指标推演 |
| 笼舍 | 稳定 6.9 | 垫料含水 | 换垫料 | 耐寒畏热，26℃ 即热应激 |
| 蜂箱 | 稳定 6.6 | 巢内含水 | 加湿盘 | 需 34℃ 恒温，手动够不到 |
| 暗室 | 稳定 6.0 | 菌床含水 | 喷水 | 要近乎无光，白天调适效果差（光照按 12% 折算） |

> 栖息地只决定"物理模型"，**界面用词与提示文案按物种覆盖**。蜂箱住蜜蜂时是「巢脾状态」，住仓鸮时是「巢箱卫生」；暗室养平菇时是「基质状态」，养蚕时是「蚕座卫生」。

> **蜜蜂是刻意设计的"产线门槛"物种**：手动调节受 ±3℃ 偏移 + 单台设备限制，最多只能推到适生 70；装满保温层能到 100 以下的中段；只有上自动调控 Lv2 才能稳在 100。这是让"升级温室"有真实回报的设计，而不是数值没调好。

## 核心机制

- **收益平衡**：18 物种按「基础单价 × 产量 ÷ 总天数」统一折算日收益，曲线比控制在约 4 倍内（最难养的物种回报最高、最易养的最低但不掉队）。2026-11 配平：番茄 4.2→3.4，帝王蝶 1→1.8、林蛙 1→1.5、水母 1.2→2.0、芦荟 1.6→2.0、平菇 1.6→2.0。
- **种子定价与收成联动**：种子价不是「难度 × 固定值」，而是由该物种 B 级品质的收成反推：`seedPrice = harvestValue(B) ÷ (1 + 利润率)`，按难度取利润率（★30% / ★★55% / ★★★95% / ★★★★135%）。这样任何物种用普通水平（B 级）玩都不亏本，难度越高的物种利润率越高——打好了回报显著，打不好也不至于血本无归。收获基准同时上调（`18 + base×26` → `34 + base×34`），一轮净利 21–66 币，约 3–6 轮可攒够第二培育位的 180 币。
- **环境适生度**：温度、湿度、光照（按当日累计日照小时数）、土壤含水、pH，各自有适宜区间。区间内为 1，越界线性衰减；综合分 = 平均值 ×0.55 + 最短板 ×0.45（短板决定成败）。
- **营养配比**：N/P/K 三个维度，每个阶段需求不同。白线是需求值，色条是当前供给，偏差过大生长速率下降。
- **生长速率**：`rate = ((综合分 − 15) / 85)^1.15`。低于 50 分显著变慢，低于 25 分开始累积胁迫。
- **健康与死亡**：分数 > 70 回血，< 50 掉血；温度越过耐受极限（±8℃）触发急性胁迫，约 2 个游戏日致死。
- **病害**：健康低于 65 时概率出现叶斑病/白粉病/蚜虫（水生为水霉病/氨中毒），拖久了会死，可用"防治"花 30 币清除。
- **品质评级**：`全程适生分均值×0.52 + 末健康×0.18 + 最低健康×0.14 + 末段适生×0.16`，病害/极端环境额外扣分；S 级要求全程适生均值 ≥89（硬门槛封顶：均值<89→≤89，<78→≤74，<62→≤60）。S/A/B/C/D 对应不同收获量与金币。
- **循环**：收获后自动留下 1 粒（A 级以上 2 粒）自留种，可直接开下一轮；培育位可花金币扩建到 4 个。
- **多代选育**：每粒种子带「代数 G」与「活力」。
  - 子代活力 = 母本活力 × 0.62 + (本代品质 − 75) × 0.30，再叠加突变：2% 概率 ±10 大突变，12% 概率 ±3 波动。负数额外乘 0.82 做「回归拉力」，防止雪球。
  - 活力范围 −8 ~ +30。每 1 点活力带来 **评分 +0.55**、**生长速度 +1.2%**。实测曲线：一直留 S 级（95 分）约 15 代收敛到 +15.7（评分 +8.6、生长 ×1.19），A 级收敛 +7.8，B 级维持 0，C 级稳定在 −7.5 附近——选育是长期投入，不是三代封顶。
  - 品级：≥9 优系（金）、≥4 良种（绿）、≥−2 普通、<−2 劣变（红）。
  - 持有多种子时会弹出选择框，按活力排序，不强制播种最优粒。
- **杂交育种**（图鉴 → 杂交育种）：选两粒同种种子作亲本 A/B。
  - 子代活力 = 双亲均值 + 杂种优势（0.8~2.4），且不超过最优亲本 +3；代数取两者较大值 +1。
  - 突变率高于自然繁殖：**6%** 大突变（±12）、**20%** 小波动（±4）。
  - 消耗两粒亲本 + 60 币场地费，子代记录血缘（最近 4 条）。
- **季节与市价**：每 10 个游戏天轮换春→夏→秋→冬，四季各有旺/淡季。
  - 市价系数：旺季 ×1.35、平季 ×1.0、淡季 ×0.72。番茄夏旺冬淡，草莓春旺夏淡，向日葵夏秋双旺，林蛙春旺秋淡，锦鲤夏旺冬淡。
  - 季节同时改变环境：冬 −7℃/−9% 湿度/−2h 光照，夏 +2.5℃/−5% 湿度/+1.4h 光照。**恶劣季节设备效率打 8 折**，所以冬季更难养。
  - 订单生成偏好旺季物种（权重 3:2:1），旺季的高品质货能卖出最高价。
  - 「一键调到适宜」会自动扣除季节偏移，不用手动换算。
- **温室改造**（顶栏「温室 x/17」）：一次性投入、永久生效，共 6 项各 2–3 级。
  | 改造 | 效果 | 价格 |
  |---|---|---|
  | 保温层 ×3 | 寒冷压制 −2.6℃/级，设备效率 +10%/级 | 180/420/900 |
  | 补光系统 ×3 | 季节光照压制 −0.8h/级 | 150/360/780 |
  | 滴灌网 ×3 | 每日少蒸发 2.2%/级，季节水分压制 −2/级 | 120/300/650 |
  | 通风降温 ×2 | 夏季高温压制 −1.4℃/级 | 200/520 |
  | 育苗架 ×3 | 收获量 +12%/级（售价 +9.6%/级） | 260/600/1200 |
  | 自动调控 ×2 | 温/湿/光自动维持，Lv2 含自动补水；**每槽 4 币/天运行费** | 700/1600 |
  - 手动温度修正**上限 ±3℃**，超出部分必须靠设备与改造补，这是升级存在的意义。
  - 改造只在"压制"方向生效，绝不制造反向优势（冬暖不会把温度推高到夏季水平）。
  - **自动调控的运作方式**：每天推进时按当前阶段最优值反解"偏移 + 设备"，并做闭环修正（设备开后按真实读数回算偏移，避免超调）。偏移上限自动模式放宽到 ±4.5℃/±14%/±4.2h，设备可成组运行（光照缺口大时开两组补光）；手动「一键调到适宜」只有 ±3℃ 与单台设备，同一场景下适生 66 对 100——这就是 2300 币换来的差距。
  - 运行费让自动化不是无脑解：4 个槽位全自动（Lv2）每天 32 币，需靠订单与旺季溢价覆盖。冬季不装保温层也能做到适生 100，但电费照付。
- **经营手账（顶栏「手账」）**：五章 20 步主线，与每日目标的"当天周转"互补，是整段经营的成长线。每步达成即自动结算金币与经验（不需要手动领取），章节全通给称号：立足温室 / 匠心培育 / 行家里手 / 万物有灵 / 温室主人。与成就共用检查节奏（收获、跨天、交付后统一判定），称号显示在手账标题旁。第五章「规模」专为第 30–60 天设计——四章走完后不再有"下一步干什么"的空窗期。
- **收购订单**（顶栏「订单」）：甲方按物种、最低品质、有时还要求代数下单，按订单价收购，通常高于散卖。
  - 8 类客户：社区市集（×1.15，门槛低量多）、自然课堂（×1.40，B 级）、湖畔餐厅（×1.65，A 级）、**花艺工作室（×1.85，品质 84+）**、**摄影棚（×2.40，90+ 且 G3 以上）**、育种研究所（×2.10，A 级且 G2+）、**中药铺（×1.75，专收芦荟/蜜蜂/平菇/鸡）**、**水族馆（×1.62，专收水生生物）**。带「专收」的客户只做本行生意，让药用栽培与水族展示两条路线各有稳定买家。
  - 定价锚定散卖单价：`散卖 × 客户倍率 × (品质/78)^1.15 × 数量^-0.22`，并设硬性保底（不低于同品质散卖 ×1.05），保证任何订单都不会比散卖更亏。
  - 定价 = `基础价 × 客户倍率 × (品质/78)^1.4 × 数量^-0.35`，并有保底报酬，保证高要求小单不比散卖亏。
  - 同时挂 3 单，有效期 12 天；过期自动清理并补新单；也可花 20 币手动刷新。
  - 交付时**优先消耗刚好达标的最低品质批次**，好货留给更贵的订单或散卖。
  - **熟客度**：同一客户累计交满 3 单成为「熟客」（订单溢价 +8%），满 6 单成为「连锁客户」（+15%）。熟客有 30% 概率下**连锁单**——同一物种 3 件、品质门槛降 8 分、单价 ×1.35，卡片带金色「连锁单」标记，一轮最多 1 张。
- **收获仓分批计价**：产物按品质分别入库，S/A/B/C/D 各自单价不同（品质 93 与 55 的同一作物价格差 60%+），不再统一按 78 分折算。
- **昼夜与天气**：14 秒 = 1 游戏天，有晴/多云/小雨/闷热/降温五种天气轮转；夜里光照归零。季节会改写天气：**冬季不会出现「闷热」，夏季不会出现「降温」**。
- **图鉴**：每见过一个阶段即解锁，解锁进度与三条科普问答构成学习档案。
- **设备操作台**：加温/降温、加湿/除湿、补光/遮阳六台设备，点一下即开；相反的两台自动互斥。另有"浇水"（含水 +22%，但会随天蒸发）与"一键调到适宜"快速对齐（单台设备、偏移 ±3℃，属手动兜底）。
- **收获结算**：收获时弹出结算卡，展示等级徽章、品质分、产量/金币/经验/自留种四项数据、子代代数与活力（含母本/本代拆解与突变标记），并随机附一条该物种的科普问答。
- **成就**：28 项，分七类（培育 / 品质 / 经济 / 图鉴 / 选育 / 经营 / 宠物），在图鉴顶部按组展示。已解锁显示日期，未解锁但有进度的直接显示差额（如「8600/10000 币」），不用猜还差多少。解锁即发金币奖励（四档：60 / 100 / 160 / 260 币，共 3240 币），奖励金额直接标在成就卡上。

- **音效**：全部由 Web Audio 现场合成，不加载任何音频文件（单文件版断网也有声）。播种/浇水/设备/收获/金币/升级/成就/事件/病害/死亡各有独立音色，收获音按品质加音高（S 级多一层高音）。顶栏一键静音，状态存在 localStorage。

- **每日目标**（顶栏「目标 x/3」）：每天刷新 3 个可完成的小目标（浇水、配肥、出货、接单、收获、保持状态、防治、设备调度等），达成后手动领取金币与经验；三个全领完额外给宝箱（60 + 天数×2 币）。这是新手期最重要的周转资金来源。宠物任务（拾捡鸡蛋、陪伴时光）带 only 条件过滤——**没养对应宠物时绝不会抽到**，养了才会进池，避免出现"永远完成不了"的死任务。

偏好保存在 `localStorage` 的 `naturelab.prefs`，**与存档分离**——切换存档不会重置：

| 项目 | 行为 |
|---|---|
| 音效音量 | 0–100 连续滑杆，落到总线增益（二级曲线，低音量区更细腻）。与「🔊」静音开关并存，静音优先 |
| 减少动效 | 关闭粒子、飘字、卡片入场、场景呼吸。首次运行会跟随系统 `prefers-reduced-motion`，之后系统再变化也会被动跟随 |
| 色盲友好 | 提升对比度，状态改「图标 + 颜色」双通道（■ 病害 / ▲ 胁迫）。品质本就用 S/A/B/C/D 字母呈现，天然不依赖颜色 |
| 界面字号 | 小 0.92 / 中 1.0 / 大 1.12，只放大正文，不改布局比例 |
| 氛围音乐 | 程序化生成的环境铺底，**独立于音效静音**，有自己的开关与音量。分 5 套场景变奏（温室/夜/水/蜂房/暗房）+ 4 季移调色彩（夏+2、秋−3、冬−5 半音），随培育物种、昼夜、季节自动切换；收获/成就奏上行琶音、死亡/恶性事件涌低音小二度（bgmAccent） |
| 切后台自动暂停 | 标签页失焦即停表，回来继续，避免挂机涨进度 |
| 全屏 | 沉浸模式，也可按 F11；Esc 退出时按钮文案自动同步 |

## 远缘嫁接

把两个不同物种的砧木与接穗拼在一起，赌一个"本不该存在"的品种。

**成功率 = 亲和度 × 方向修正 × 季节系数 + 活力加成**

| 因素 | 说明 |
|---|---|
| 亲和度 | 40 组预设组合（番茄×草莓 42%、蚕×帝王蝶 40%、鸡×鸭 36%、犬×猫 34%、猫×鸮 20%、仓鸮×蜜蜂 16%…），表里没有的组合按 5% 处理——**同科才可能有戏** |
| 方向修正 | 谁当砧谁当穗影响生根与吸水能力，如青蛙做砧 +12%、做穗 −8%；陆龟做穗 +12%（甲壳耐旱）但做砧 −14%（根系弱），仓鸮正好相反 |
| 季节 | 冬季 ×0.8，愈合组织形成慢 |
| 活力加成 | 亲本活力越高，成功率略微上浮（每点 +1.2%） |

结果有四档：**接活**（进嫁接体库，可播种，带产量/售价加成）、**假活**（当时看着活，随后枯死）、**不亲和**（当场失败）、**双方种质不足**（不允许开始）。
接活率刻意压在 30–45%：这是实验，不是流水线。

## 3D 场景

舞台背景由 Three.js 实时渲染，跟随培育位自动切换：

| 栖息地 | 场景构成 |
|---|---|
| 土壤 / 笼舍 | 温室：拱顶钢架 + 檩条、两排带支腿的台架、球形叶簇盆栽、中央走道 |
| 池塘 | 水体：60×60 细分水面做顶点波动、26 块岸边石、40 株摆动的锥形水草 |
| 蜂箱 | 巢内：135 个内凹六棱巢房（InstancedMesh）+ 34 个蜜盖 + 木质巢框 + 箱壁 |
| 暗室 | 菌床 / 蚕房：4 层出菇架、28 个菌包、112 顶伞盖、浓雾 |

> 3D 场景按**栖息地**切换，不按物种。蜂箱场景里既可能关着蜜蜂，也可能栖着仓鸮；暗室既长平菇，也可能摊着蚕匾。这是有意的取舍——一个栖息地一个场景，新增物种不必新增建模，代价是场景里看不出物种差异，物种差异交给前景的阶段图和文案承担。

**设计约束**
- 零贴图依赖：几何体全部程序化生成；地面/木材/水面用 Canvas 现画的贴图
- 静态背景图**永远垫在最底层**，3D 只是叠上去的一层 → 任何时刻 3D 挂了都还有完整画面
- WebGL 不可用 → 按钮置灰、不渲染，不出现黑画布
- 帧率哨兵：连续 1.5 秒低于 18fps 先自动降分辨率，仍是低帧则自己关掉退回背景图
- 开关状态存 `localStorage`，与存档无关
