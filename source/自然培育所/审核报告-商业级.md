## 3. 主要发现与处理

### P0 · 阻断发行

**P0-1 没有任何用户/档案层**
- 现象：所有玩家共用一套 `naturelab.save.v1.*` 键；同一浏览器无法区分两个人；设置、教学进度、成就全部混在一起。
- 影响：共用电脑场景直接串档；无法做「多周目不同玩家」；商业化上缺少最基本的用户概念。
- 处理：新增 `js/account.js`，实现本机多用户档案：
  - 档案注册表 + 当前档案指针 + 每档案独立命名空间 `naturelab.u<id>.*`
  - 新建 / 切换 / 重命名 / 换头像 / 删除，删除即清空该档案全部键
  - 旧版全部键在首次启动时自动迁入默认档案「培育员」，原键删除，零丢档
  - 所有既有模块（存档、设置、音效、BGM、3D、教学）统一走 `storeKey()`，不再有绕过命名空间的裸键

**P0-2 存档损坏会静默开新档**
- 现象：`loadGame()` 解析失败直接 `return null`，上层用默认状态开局，下一次自动保存就覆盖原始数据。
- 处理：
  - `validateSaveShape()` 结构校验（版本、槽位、天数、金币、数组字段）
  - 主档失败 → 隔离原文到 `...save.v1.corrupt` → 依次尝试 3 份备份 → 成功则回滚并提示
  - 导入存档同样走校验，拒绝未来版本与畸形结构

**P0-3 保存失败完全静默**
- 现象：`saveGame()` 的 `catch(e){}` 吞掉配额满/隐私模式错误，玩家以为在玩，实际几小时进度全丢。
- 处理：`saveGame()` 返回布尔值并回调 `window.__nlOnSaveError`；`app.js` 显示常驻警示条 + toast，引导导出与清理。

### P1 · 明显影响体验或信任

**P1-1 没有隐私说明与数据控制权**
- 处理：档案面板内置「数据与隐私」区，明确：仅本机、无网络、无埋点、清理站点数据会删档；提供单档案/全档案导出、导入、全量清除。

**P1-2 无全局异常兜底**
- 现象：任一渲染异常即白屏，玩家只能刷新，且不知道存档是否还在。
- 处理：`app.js` 捕获 `error` / `unhandledrejection`，节流提示；12 秒启动看门狗在初始化失败时给出「重新加载 / 导出存档 / 浏览器要求」。

**P1-3 弹窗无焦点管理**
- 现象：键盘用户打开弹窗后 Tab 会跑到背后的界面；关闭后焦点丢失。
- 处理：统一 `role="dialog"` + `aria-modal`，Tab 循环限制在当前层，关闭后焦点归还；锁屏同样纳入。

**P1-4 窄屏内容被裁掉**
- 现象：≤960px 时 `.app` 改为 `height:auto`，但 `body` 仍是 `overflow:hidden`，页面下半部分无法滚动（实测 539×588 视口下内容高 1153px）。
- 处理：窄屏改为 `html,body{height:auto}` + `overflow-y:auto`，并加 `safe-area-inset-bottom`；实测恢复可滚动。

**P1-5 PIN 明文风险（设计前）**
- 处理：PIN 仅存随机盐 + SHA-256；无 WebCrypto 时回退 20000 轮 FNV；5 次失败冷却 30 秒；UI 明示「不是加密，能开 DevTools 的人可绕过」。不做虚假安全承诺。

**P1-6 版本信息不一致**
- 现象：`about` 弹窗硬编码 1.10，`aboutVer` 初始 1.0，开发文档写 v1.10。
- 处理：统一由 `NL_APP_VERSION` 驱动，全链路 2.0；更新日志补 v2.0 条目。

### P2 · 打磨项

- 导出文件名带档案名与天数，避免多档案导出互相覆盖。
- 档案名/头像等用户输入全部 `nlEsc()` 转义，杜绝自伤害型 XSS。
- `beforeunload` / `pagehide` / `visibilitychange` 三重落盘，降低关页丢档概率。
- 导入文件 8MB 上限、最多 20 个档案，避免恶意/误操作撑爆存储。
- 导出/导入保留原 PIN 设置，换设备后安全边界不降级。
- 关于页补充「适龄提示：全年龄」与健康游戏忠告，补齐国内发行常见合规项。
- 文档修正：存档位实际为 3 个（原文写 4 个），新增档案层、键名布局、发布自检流程。

## 4. 用户体系设计（本次核心）

### 4.1 为什么不做「注册登录」

本作是纯前端、零网络请求的离线游戏，没有服务端可以托管账号。做一个假的登录框只会制造「我的账号在云端」的误解。商业上正确的等价物是**本机多用户档案**：

- 一个浏览器 = 一台设备；一个档案 = 一位玩家
- 档案之间完全隔离：存档、设置、教学、成就、图鉴
- 用 PIN 解决「同一台电脑上的误入/窥探」
- 用导出/导入解决「换设备/备份」

### 4.2 数据模型

```text
naturelab.accounts.v1        [{ id, name, avatar, createdAt, lastPlayedAt, pin? }]
naturelab.account.current    当前档案 id
naturelab.u<id>.save.v1.slot1..3
naturelab.u<id>.save.v1.slots        槽位摘要
naturelab.u<id>.save.v1.bak<n>_<i>   自动备份
naturelab.u<id>.prefs / sound / vol / bgm / bgmVol / scene3d / tutor / guide
```

### 4.3 关键流程

- **首次启动**：无注册表 → 创建「培育员」→ 迁移旧键 → 提示可改名/加 PIN。
- **启动**：当前档案有 PIN → 全屏锁屏，游戏主循环暂停（`NL.locked()` 参与 `loop` 门控）。
- **切换**：先保存当前档 → 写当前指针 → 重载页面；目标档案若有 PIN，重载后再次锁屏。
- **删除**：清空该档案命名空间下全部键 + 注册表条目；当前档案不可直接删（先切走）。
- **忘记 PIN**：明确告知不可找回，只能清除该档案数据（二次确认）。

### 4.4 安全边界（明确披露）

- PIN 是访问控制，不是加密；localStorage 对本机用户可读。
- 不防御拥有系统权限或 DevTools 的人；共用电脑请使用独立操作系统账户。
- 本作不上传任何数据，因此不存在服务端泄露面，也不存在「找回密码」。

## 8. 尚未覆盖 / 需要产品决策

以下不是代码缺陷，而是「离线单机」与「联网商业产品」之间的能力差距，需要明确取舍：

1. **跨设备云同步**：需要服务端、账号体系、隐私政策与合规评估；当前明确不做。
2. **支付/内购**：无商业化收费点；若要上架，需要平台 SDK 与订单风控。
3. **真实用户分析**：当前零埋点。若引入，必须先加同意弹窗与可关闭开关，并更新隐私说明。
4. **内容分级与素材授权**：AI 生成素材的商用授权链需要法务确认；建议保留生成记录与授权文件。
5. **19MB 单文件**：建议按栖息地拆包并预加载首屏，或提供「轻量版」。
6. **`ui.js` 3200+ 行**：建议拆分为 `ui-stage` / `ui-panels` / `ui-loop`，降低后续维护成本。
7. **PIN 强度**：4 位 PIN 只有 1 万种组合，本地离线可暴力尝试；已加 30 秒冷却，但不防离线拷贝。若需更强，应改为口令 + PBKDF2/Argon2。
8. **辅助功能**：色盲/减动效/字号已有；仍建议补一次真实读屏（NVDA/VoiceOver）走查与高对比模式。
